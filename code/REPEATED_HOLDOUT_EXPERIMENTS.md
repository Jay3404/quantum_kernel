# PCA7 전체 재분할 반복 비교

현재 실행은 `cmc_pca7_repeated_20261020`, 고정 설계는 `docs/cmc_pca7_repeated_protocol_20261020.json`이다. 사용자가2026-10-20에 시드10,20,...,100과 테스트 고객까지 재분할하는 PCA7 재실험을 명시 요청했다. 이전 고정 테스트 PCA7과 PCA9 결과·소스·체크포인트는 보존한다.

German Numeric, South German, HMEQ, Taiwan 전체와 기존 네 방법, RBF/QSVC, 무주입·셔플·상수·분리형 양자 대조 및 원특성/PCA 고전 참조를 유지한다. 방법을 다시 발굴하거나 좋은 시드만 고르지 않는다. 전체1160작업이다.

각 시드에서 층화80/10/10을 다시 나눈다. 학습80%는 `random_state=seed`, 검증/테스트는 holdout20% 안에서 `seed+103`을 사용한다. 같은 시드 안의 모든 방법은 같은 분할을 쓴다. 전처리·PCA·5OOF LR/XGB 위험 추정을 모두 새로 학습한다. LR sigmoid 보정은 내부3폴드·ensemble=False다. 같은 시드의 위험점수는 방법 간 공유하지만 이전 실행의 점수·모델은 가져오지 않는다.

모든 학습80%를 쓰며 최종은 단일SVM이다. 큰 자료512랜드마크 근사 탐색/전체행 정확 최종 적합/자기 검증 임계값을 구분한다. 모든 계획 모델과 임계값을 잠근 후 테스트를 한 번 공개한다. 테스트 공개 후 새 학습·선정은 금지한다.

서로 다른 테스트 집합으로 반복하므로 기존 고정고객 bootstrap/sign-flip을 그대로 사용하지 않는다. 반복당 짝 비용차이에 근사 corrected resampled t, df9, 분산계수1/10+n_test/n_train=0.225를 적용하고184개 계획 대비 전체에 Holm을 적용한다. 겹치는 고객·시드를 독립 테스트 표본으로 세지 않는다. 고객 재등장/집합 중첩은 `test_cohort_coverage.csv`, `test_cohort_overlap.csv`에 남긴다. 같은 자료/시드가 과거 탐색에 쓰인 한계는 그대로이며 독립 외부 확인 실험이라고 부르지 않는다.

최대27개 단일스레드 새 작업 프로세스, CPU85% 입장 기준, 메모리80%와8GiB 추가 여유다. 전체 HMEQ/Taiwan16개 측정으로 검색/정확 적합 예산과 별도 정확 슬롯을 결정한다. 압력이 높으면 새 작업만 기다리고 정상 학습을 종료하지 않는다. 실제85%를 항상 채운다는 보장은 없다. CPU Aer7/8큐비트 정확 상태벡터와 장치별 잠금 GPU Gram을 구분한다.

첫 PCA9는 사용자 요청으로 새 배정을 중단하고 진행 작업의 종료·저장을 기다린 뒤 별도 운영 영수증과 체크포인트를 보존한다. PCA7 재실험과 감사를 마친 뒤에만 새 시드/분할로 PCA9를 별도 실행한다. 이전 PCA9의 불일치 분할 결과를 이어 붙이지 않는다.

실행 전 소스·기술 검사·전처리 폴드·새 위험 추정·메모리 측정을 검증하고 동결한다. 실패를 보존하며 자동 재시도하지 않는다. 실제 상태는 서버의 metadata/monitor/operations/supervision을 읽는다. 정상 진행은 알리지 않고 최초 시작·실패·필요한 조치·완료만 알린다. 최종 결과와 모든 체크포인트를 로컬에 동기화한 뒤 고정 서버 환경에서 `code/validate_repeated_holdout.py --run-id cmc_pca7_repeated_20261020`으로 감사한다.
